## What Is White-Labeling?

White-labeling is the process of customizing the Admin application with your own branding - logos, colors, and titles. This is important when:

- Building a SaaS product
- Creating a custom CMS for clients
- Meeting corporate branding guidelines
- Supporting multi-tenant setups with different branding per tenant

Webiny makes white-labeling straightforward through simple Admin extensions.

## Creating the AdminBranding Extension

Let's create a white-label extension step by step. We'll customize:

1. The application title
2. The logo
3. The color theme

### Step 1: Create the Extension Folder

Create a new folder structure in your `extensions/` directory:

<CodeBlock
  language="text"
  code={`extensions/
└── AdminBranding/
    ├── AdminBranding.tsx
    └── logo.png`}
/>

Add your logo image to this folder (use your company logo or any image for now).

### Step 2: Create the Theme Extension

Create `extensions/AdminBranding/AdminTheme.tsx`:

<CodeBlock language="tsx" filename="extensions/AdminBranding/AdminTheme.tsx" code={`import React from "react";
import { AdminConfig } from "webiny/admin/configs";

const { Theme } = AdminConfig;

const AdminTheme = () => {
return (
<AdminConfig.Public>
<Theme.Color palette={"primary"} color={"purple"} />
<Theme.Color palette={"secondary"} color={"green"} />
</AdminConfig.Public>
);
};

export default AdminTheme;`} />

This extension:

- Sets the primary color to purple
- Sets the secondary color to green
- Uses `AdminConfig.Public` to make this configuration available to the Admin app

<Callout type="info" title="Color Options">
  You can use any valid CSS color value: named colors (like "purple", "green"),
  hex codes ("#6B46C1"), or RGB values.
</Callout>

### Step 3: Create the Logo and Title Extension

Create `extensions/AdminBranding/AdminTitleLogo.tsx`:

<CodeBlock language="tsx" filename="extensions/AdminBranding/AdminTitleLogo.tsx" code={`import React from "react";
import { AdminConfig } from "webiny/admin/configs";
import squareLogo from "./logo.png";
import horizontalLogo from "./logo.png";

const { Title, Logo } = AdminConfig;

const AdminTitleLogo = () => {
return (
<AdminConfig.Public>
<Title value={"ACME Corp"} />
<Logo
squareLogo={<img src={squareLogo} alt={"ACME Corp"} />}
horizontalLogo={<img src={horizontalLogo} alt={"ACME Corp"} />}
/>
</AdminConfig.Public>
);
};

export default AdminTitleLogo;`} />

This extension:

- Sets the application title to "ACME Corp"
- Configures both square and horizontal logos (for different layouts)
- Imports the logo image from the same folder

<Callout type="hint" title="Logo Formats">
  The Admin app uses two logo variants: square (for the sidebar) and horizontal
  (for the login page). You can use the same image for both or provide different
  images for each.
</Callout>

### Step 4: Register the Extensions

Add both extensions to your `webiny.config.tsx`:

<CodeBlock language="tsx" filename="webiny.config.tsx" code={`import React from "react";
import { Admin, Infra } from "webiny/extensions";
import { Cognito } from "@webiny/cognito";

export const Extensions = () => {
  return (
    <>
      <Infra.Aws.DefaultRegion name={"us-east-1"} />
      <Cognito />

      {/* Admin branding */}
      <Admin.Extension src={"/extensions/AdminBranding/AdminTitleLogo.tsx"} />
      <Admin.Extension src={"/extensions/AdminBranding/AdminTheme.tsx"} />
    </>

);
};`} />

### Step 5: Test Locally

Start the Admin development server:

<CodeBlock
  language="bash"
  filename="Terminal"
  code={`yarn webiny watch admin`}
/>

Open http://localhost:3001 in your browser. You should see:

- Your custom logo
- "ACME Corp" as the application title
- Purple primary color and green secondary color

## Combining Into a Single Extension

You can also combine both extensions into a single file for simplicity:

Create `extensions/AdminBranding/AdminBranding.tsx`:

<CodeBlock language="tsx" filename="extensions/AdminBranding/AdminBranding.tsx" code={`import React from "react";
import { AdminConfig } from "webiny/admin/configs";
import squareLogo from "./logo.png";
import horizontalLogo from "./logo.png";

const { Title, Logo, Theme } = AdminConfig;

const AdminBranding = () => {
return (
<AdminConfig.Public>
{/* Title */}
<Title value={"ACME Corp"} />

      {/* Logo */}
      <Logo
        squareLogo={<img src={squareLogo} alt={"ACME Corp"} />}
        horizontalLogo={<img src={horizontalLogo} alt={"ACME Corp"} />}
      />

      {/* Theme colors */}
      <Theme.Color palette={"primary"} color={"purple"} />
      <Theme.Color palette={"secondary"} color={"green"} />
    </AdminConfig.Public>

);
};

export default AdminBranding;`} />

Then register only this single extension in `webiny.config.tsx`:

<CodeBlock
  language="tsx"
  filename="webiny.config.tsx"
  code={`<Admin.Extension src={"/extensions/AdminBranding/AdminBranding.tsx"} />`}
/>

<Callout type="success" title="Simpler Approach">
  Combining related configurations into a single extension file keeps your
  project organized and makes it easier to manage branding changes.
</Callout>

## Customizing for Different Environments

You can apply different branding based on the environment:

<CodeBlock language="tsx" filename="extensions/AdminBranding/AdminBranding.tsx" code={`import React from "react";
import { AdminConfig } from "webiny/admin/configs";
import logo from "./logo.png";

const { Title, Theme } = AdminConfig;

const AdminBranding = () => {
// Get the current environment
const isProd = process.env.WEBINY_ENV === "prod";

return (
<AdminConfig.Public>
<Title value={isProd ? "ACME Corp" : "ACME Corp (Dev)"} />
<Theme.Color palette={"primary"} color={isProd ? "purple" : "orange"} />
</AdminConfig.Public>
);
};

export default AdminBranding;`} />

This shows "ACME Corp (Dev)" in non-production environments and uses orange as the primary color to make it visually distinct.

## Tenant-Specific Branding

For multi-tenant setups, you can apply different branding per tenant:

<CodeBlock language="tsx" filename="extensions/AdminBranding/AdminBranding.tsx" code={`import React from "react";
import { AdminConfig } from "webiny/admin/configs";
import { useTenantContext } from "webiny/admin/tenancy";
import acmeLogo from "./logos/acme.png";
import globexLogo from "./logos/globex.png";

const { Title, Logo, Theme } = AdminConfig;

const AdminBranding = () => {
const { tenant } = useTenantContext();

// Different branding per tenant
const branding = {
acme: {
title: "ACME Corp",
logo: acmeLogo,
color: "purple",
},
globex: {
title: "Globex Corporation",
logo: globexLogo,
color: "blue",
},
};

const config = branding[tenant.id] || branding.acme;

return (
<AdminConfig.Public>
<Title value={config.title} />
<Logo
squareLogo={<img src={config.logo} alt={config.title} />}
horizontalLogo={<img src={config.logo} alt={config.title} />}
/>
<Theme.Color palette={"primary"} color={config.color} />
</AdminConfig.Public>
);
};

export default AdminBranding;`} />

Each tenant gets completely independent branding while maintaining a single codebase.

<Callout type="info" title="Scaling to Many Tenants">
  This hardcoded approach works well when you have a handful of tenants (up to
  ~10). If you're managing many tenants or tenants are added continuously,
  consider storing branding configuration in Headless CMS instead. This approach
  is covered separately in the Webiny documentation portal.
</Callout>

## Summary

White-labeling in Webiny is straightforward:

- **Simple extensions** using `AdminConfig` components
- **Title, Logo, and Theme** are the main customization points
- **Combine or separate** - Use single or multiple extension files
- **Environment-specific** - Different branding per environment
- **Multi-tenant support** - Different branding per tenant

The extension system makes it easy to create fully branded Admin applications. In the next lesson, we'll explore debugging and best practices for Webiny development.
