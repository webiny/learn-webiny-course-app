## What is the API Playground?

The **Webiny API Playground** is a built-in GraphQL IDE (Integrated Development Environment) that comes with every Webiny project. It's based on GraphiQL, a popular tool for exploring and testing GraphQL APIs.

The API Playground allows you to:

- **Explore your API schema** - See all available queries, mutations, and types
- **Test queries and mutations** - Execute GraphQL operations in real-time
- **View documentation** - Access auto-generated docs for all API operations
- **Debug responses** - See exactly what data your API returns
- **Experiment safely** - Try out queries before implementing them in your app

<Callout type="info">
  The API Playground is only available in development environments by default.
  In production, it's disabled for security reasons.
</Callout>

## Accessing the API Playground

The API Playground is accessed directly from the **Webiny Admin** application.

### How to Open the API Playground

1. **Open the Webiny Admin** application in your browser
2. Click on **API Playground** in the left sidebar
3. You'll see tabs for different APIs at the top:
   - **Main API** - Core Webiny GraphQL API
   - **Headless CMS - Manage API**
   - **Headless CMS - Read API**
   - **Headless CMS - Preview API**

### The Three HCMS API Playgrounds

Each Headless CMS API has its own playground tab:

**Manage API**

- **Purpose**: Test CRUD operations for managing content
- **Returns**: All revisions, draft and published content, includes `meta` field
- **Mutations**: Create, update, delete, publish, unpublish
- **Authentication**: Required (automatically handled when logged into Webiny Admin)

**Read API**

- **Purpose**: Test queries for published content (public-facing)
- **Returns**: Published content only, no `meta` field
- **Mutations**: None (read-only)
- **Authentication**: Required (via API key)

**Preview API**

- **Purpose**: Test queries for latest revisions including drafts
- **Returns**: Latest revision (published or draft), includes reference to unpublished entries
- **Mutations**: None (read-only)
- **Authentication**: Required (via API key)

### Finding Your API URLs

Each API has its own URL endpoint following this structure:

<CodeBlock
  language="text"
  code={`https://{your-domain}/cms/{manage|read|preview}`}
/>

**Examples:**

- Read API: `https://d1ud9w3i9i7d77.cloudfront.net/cms/read`
- Preview API: `https://d1ud9w3i9i7d77.cloudfront.net/cms/preview`
- Manage API: `https://d1ud9w3i9i7d77.cloudfront.net/cms/manage`

**To find your specific URLs:**

**Option 1: Via Webiny CLI**

Run `yarn webiny info` in your terminal to see all your API endpoints:

<Image
  src="/images/headless-cms/webiny-info-output.png"
  alt="Webiny info command output showing API endpoints"
  caption="The yarn webiny info command displays all your Webiny API endpoints."
/>

**Option 2: In the API Playground**

The URL for the currently selected API is displayed at the top of the playground interface, next to the "COPY CURL" button.

<Callout type="info">
  When using the API Playground within Webiny Admin, you're automatically
  authenticated. When accessing these URLs from your applications, you'll need
  to provide an API key.
</Callout>

## Understanding the Playground Interface

The API Playground interface has several key areas:

### 1. Query Editor (Left Panel)

This is where you write your GraphQL queries and mutations. It features:

- **Syntax highlighting** for GraphQL
- **Auto-completion** (press Ctrl+Space or Cmd+Space)
- **Inline error detection**

### 2. Response Panel (Right Panel)

Displays the results of your queries, including:

- **Data returned** from the API
- **Error messages** if something goes wrong
- **Execution time** for performance monitoring

### 3. Documentation Explorer

Click the "Docs" button to access:

- **All available queries and mutations**
- **Field types and descriptions**
- **Required vs optional fields**
- **Nested type definitions**

### 4. History

View previously executed queries (useful for iterating on queries)

### 5. Variables Panel (Bottom)

Define variables for your queries to make them reusable

## Your First Query

Let's write a query to fetch all published products using the **Read API Playground**.

<Callout type="hint">
  Make sure you have at least one published product in your CMS before running
  this query. If you don't, create one following the steps in Lesson 3.
</Callout>

### Step 1: Open the Read API Playground

1. Open the Webiny Admin application
2. Click **API Playground** in the left sidebar
3. Select the **Headless CMS - Read API** tab at the top

### Step 2: Write the Query

In the query editor (left panel), enter the following query:

<CodeBlock language="graphql" title="Query: List all products">
```graphql
{
  listProducts {
    data {
      id
      name
      sku
      description
      price
    }
  }
}
```
</CodeBlock>

### Step 3: Execute the Query

Click the **Play button** (▶️) or press **Ctrl+Enter** (Cmd+Enter on Mac)

### Step 4: View the Response

The right panel will show the response:

<CodeBlock language="json" title="Response">
```json
{
  "data": {
    "listProducts": {
      "data": [
        {
          "id": "654321fedcba",
          "name": "Laptop",
          "sku": "LAP-001",
          "description": "High-performance laptop for professionals",
          "price": 1299.99
        }
      ]
    }
  }
}
```
</CodeBlock>

<Callout type="success">
  Congratulations! You've successfully executed your first GraphQL query in the
  API Playground.
</Callout>

## Exploring the Schema with Documentation

The API Playground's documentation explorer is incredibly powerful for discovering what's available in your API.

### How to Use the Documentation Explorer

1. **Click the "Docs" button** in the top-right corner of the playground
2. **Browse the root types**:
   - **Query** - All available read operations
   - **Mutation** - All available write operations (Manage API only)
3. **Click on any type** to see its fields and descriptions
4. **Navigate deeper** by clicking on field types

### Example: Exploring the Product Model

1. Open the Docs panel
2. Click on **Query**
3. Scroll to find **listProducts**
4. Click on it to see:
   - Return type: `ProductListResponse`
   - Available arguments (filters, sorting, pagination)
5. Click on **ProductListResponse** to see its structure
6. Click on **Product** to see all available fields

<Callout type="hint">
  The documentation is auto-generated from your content models. Every time you
  add or modify a content model, the schema documentation updates automatically!
</Callout>

## Working with Query Variables

Variables make your queries reusable and are essential when building real applications.

### Query Without Variables

<CodeBlock language="graphql" title="Hardcoded query">
```graphql
{
  getProduct(where: { id: "654321fedcba" }) {
    data {
      id
      name
      price
    }
  }
}
```
</CodeBlock>

### Query With Variables

<CodeBlock language="graphql" title="Query with variables">
```graphql
query GetProduct($id: ID!) {
  getProduct(where: { id: $id }) {
    data {
      id
      name
      price
    }
  }
}
```
</CodeBlock>

**Variables panel (bottom of playground):**

<CodeBlock language="json" title="Query variables">
```json
{
  "id": "654321fedcba"
}
```
</CodeBlock>

<Callout type="info">
  The `!` after `ID` means this variable is required. Without it, the variable
  would be optional.
</Callout>

## Querying Related Content

Let's query products along with their categories (assuming you've added the category reference field from Lesson 4).

<CodeBlock language="graphql" title="Query with nested reference">
```graphql
{
  listProducts {
    data {
      id
      name
      sku
      price
      category {
        id
        name
        description
      }
    }
  }
}
```
</CodeBlock>

<Callout type="hint">
  When querying reference fields, you can select any fields from the referenced
  model. The API Playground's auto-completion will help you discover available
  fields.
</Callout>

## Filtering and Sorting

The Webiny HCMS API provides powerful filtering and sorting capabilities.

### Filtering by Field Value

<CodeBlock language="graphql" title="Filter products by price">
```graphql
{
  listProducts(
    where: {
      price_gte: 1000
    }
  ) {
    data {
      id
      name
      price
    }
  }
}
```
</CodeBlock>

### Sorting Results

<CodeBlock language="graphql" title="Sort products by price descending">
```graphql
{
  listProducts(
    sort: price_DESC
  ) {
    data {
      id
      name
      price
    }
  }
}
```
</CodeBlock>

### Combining Filter and Sort

<CodeBlock language="graphql" title="Filter and sort together">
```graphql
{
  listProducts(
    where: {
      price_gte: 500
    }
    sort: price_ASC
  ) {
    data {
      id
      name
      price
    }
  }
}
```
</CodeBlock>

<Callout type="hint">
  Available filter operators depend on the field type. For numbers: `_gte`
  (greater or equal), `_lte` (less or equal), `_gt`, `_lt`. For text:
  `_contains`, `_not_contains`, `_in`, `_not_in`.
</Callout>

## Pagination

For large datasets, pagination helps manage response size and improve performance.

<CodeBlock language="graphql" title="Paginated query">
```graphql
{
  listProducts(
    limit: 10
    after: null
  ) {
    data {
      id
      name
    }
    meta {
      cursor
      hasMoreItems
      totalCount
    }
  }
}
```
</CodeBlock>

**To get the next page:**

<CodeBlock language="graphql" title="Get next page">
```graphql
{
  listProducts(
    limit: 10
    after: "eyJpZCI6IjY1NDMyMWZlZGNiYSJ9"
  ) {
    data {
      id
      name
    }
    meta {
      cursor
      hasMoreItems
      totalCount
    }
  }
}
```
</CodeBlock>

<Callout type="info">
  The `cursor` value from the previous response's `meta` should be passed as the
  `after` value for the next page.
</Callout>

## Using the Preview and Manage API Playgrounds

The Preview and Manage API playgrounds work similarly to the Read API playground.

### Authentication

When using the API Playground **within the Webiny Admin**, you're automatically authenticated based on your logged-in user session. You don't need to manually add API keys to the HTTP Headers.

<Callout type="info">
  The Webiny Admin automatically handles authentication for the Manage and
  Preview API playgrounds. API keys are only needed when accessing these APIs
  from external applications.
</Callout>

### Switching Between APIs

Simply click the tabs at the top of the API Playground to switch between different APIs:

- **Headless CMS - Manage API** - Full CRUD operations
- **Headless CMS - Read API** - Published content queries
- **Headless CMS - Preview API** - Latest revision queries including drafts

### Preview API Query Example

Switch to the **Headless CMS - Preview API** tab and run this query:

<CodeBlock language="graphql" title="Query draft products">
```graphql
{
  listProducts {
    data {
      id
      values {
        name
        price
      }
    }
  }
}
```
</CodeBlock>

The Preview API returns the latest revision of each product, whether it's published or draft.

<Callout type="hint">
  To see the status of each entry, query the Manage API which includes the
  `meta` field with status and version information.
</Callout>

## Using the Manage API Playground

The Manage API provides full CRUD capabilities for managing content programmatically. Switch to the **Headless CMS - Manage API** tab to access mutations.

### Creating a Product

<CodeBlock language="graphql" title="Mutation: Create product">
```graphql
mutation CreateProduct($data: ProductInput!) {
  createProduct(data: $data) {
    data {
      id
      name
      sku
      price
    }
    error {
      message
      code
    }
  }
}
```
</CodeBlock>

**Variables:**

<CodeBlock language="json" title="Create product variables">
```json
{
  "data": {
    "name": "Wireless Mouse",
    "sku": "MOU-002",
    "description": "Ergonomic wireless mouse with long battery life",
    "price": 29.99
  }
}
```
</CodeBlock>

### Updating a Product

<CodeBlock language="graphql" title="Mutation: Update product">
```graphql
mutation UpdateProduct($revision: ID!, $data: ProductInput!) {
  updateProduct(revision: $revision, data: $data) {
    data {
      id
      name
      price
    }
    error {
      message
    }
  }
}
```
</CodeBlock>

**Variables:**

<CodeBlock language="json" title="Update product variables">
```json
{
  "revision": "654321fedcba#0001",
  "data": {
    "price": 24.99
  }
}
```
</CodeBlock>

<Callout type="info">
  The `revision` parameter uses the format `{entryId}#{revisionNumber}`. For
  example: `654321fedcba#0001` refers to revision 1 of entry `654321fedcba`.
</Callout>

### Publishing a Product

<CodeBlock language="graphql" title="Mutation: Publish product">
```graphql
mutation PublishProduct($revision: ID!) {
  publishProduct(revision: $revision) {
    data {
      id
      meta {
        status
      }
    }
    error {
      message
    }
  }
}
```
</CodeBlock>

### Deleting a Product

<CodeBlock language="graphql" title="Mutation: Delete product">
```graphql
mutation DeleteProduct($revision: ID!) {
  deleteProduct(revision: $revision) {
    data
    error {
      message
    }
  }
}
```
</CodeBlock>

<Callout type="warning">
  Deleted entries are moved to the Trash Bin and can be restored. To permanently
  delete an entry, you need to delete it from the Trash Bin.
</Callout>

## Common Error Messages

### Error: "Cannot query field 'X' on type 'Y'"

**Cause**: You're trying to query a field that doesn't exist.

**Solution**: Check the schema documentation to see available fields, or verify your content model has the field you're trying to query.

### Error: "Variable '$X' of required type 'Y!' was not provided"

**Cause**: You defined a required variable but didn't provide it in the variables panel.

**Solution**: Add the missing variable to the variables panel at the bottom of the playground.

### Error: "Not authorized"

**Cause**: This error typically occurs when accessing APIs outside of the Webiny Admin without proper authentication.

**Solution**: When using APIs from external applications, you need to create an API key and include it in the `Authorization` header. This is covered in detail in Lesson 7: Reading Records via the API.

### Error: "Entry not found"

**Cause**: You're trying to query, update, or delete an entry that doesn't exist.

**Solution**: Verify the entry ID is correct and the entry exists in the system.

## Best Practices

### 1. Start with the Manage API

When learning within the Webiny Admin, start with the Manage API Playground since you're already authenticated and can see all data including draft content and the `meta` field.

### 2. Use the Documentation Explorer

Don't guess what fields are available - explore the schema using the Docs panel to discover all capabilities.

### 3. Test Queries Before Implementation

Always test your queries in the playground before implementing them in your application code. This saves debugging time.

### 4. Use Variables for Dynamic Queries

Get in the habit of using variables instead of hardcoding values. This makes queries more reusable.

### 5. Check Error Responses

When mutations fail, check the `error` field in the response for detailed information about what went wrong.

### 6. API Keys for External Access

The API Playground in Webiny Admin handles authentication automatically. When you need to access these APIs from your applications, you'll create API keys with specific permissions. This is covered in detail in the next lesson.
