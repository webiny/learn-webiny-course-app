# Product Listing Editor Component

In this lesson we combine the Website Builder with the Headless CMS. You'll create a custom **Product Listing** editor component that content editors can drop onto any page. The editor picks the sort order and how many products to show, and the component renders the matching published products from the Headless CMS.

**Prerequisites:**

- Website Builder starter kit running (Lesson 1)
- The Product content model set up in Webiny (from the Headless CMS chapter)
- At least 2-3 published products in Webiny

## Why combine Website Builder and Headless CMS?

The Website Builder handles layout and editorial composition. The Headless CMS holds structured, reusable content. Combining them means editors compose a page visually, while the product data stays in the CMS, where it's authored, versioned, and reused on other pages and in other apps.

## How a component gets CMS data

Editor components in the starter kit are client components. `editorComponents/index.tsx` is imported by `components/DocumentRenderer.tsx`, which is marked `"use client"`, so every component you register there runs in the browser bundle. A client component can't be `async`, and it can't read server-only environment variables, so it shouldn't fetch CMS data itself.

You don't need it to. The SDK has an input type for this: `createContentEntryInput`. It has two modes:

- **Manual mode.** The editor hand-picks one entry, or a list of entries, in the sidebar.
- **Query mode.** The editor configures a query on a fixed model (sort field, sort order, limit). The page stores the query, not the entries.

When your Next.js app loads a page with `sdk.wb.getPage()`, the SDK finds every content entry input in the page document and fetches the entries on the server before rendering. Your component receives the results in its `inputs` prop, the same way it receives a text input's value. It uses the same API key the starter kit already has in `.env`, so there's no extra SDK client or environment variable to set up.

The starter kit ships `editorComponents/ContentEntryDemo.tsx`, which shows all three variants (manual single, manual list, query). In this lesson you'll build a focused version for products, using query mode.

## Step 1: Publish some products

If you completed the Headless CMS chapter you should already have Product entries. If not, go to **Content → Product** in Webiny Admin and create 2-3 products. **Publish each one.** The Website Builder reads published content, so entries that are only saved won't show up on the live page.

<Callout type="info">
  The starter kit's "Frontend Integration" API key already has read access to Headless CMS
  entries, so you don't need to change its permissions.
</Callout>

## Step 2: Build the ProductListing component

Create `editorComponents/ProductListing.tsx`:

```tsx title="editorComponents/ProductListing.tsx"
"use client";
import React from "react";
import {
  type ComponentProps,
  type ResolvedContentEntryQuery,
  useContentEntryList
} from "@webiny/sdk-nextjs";

interface Product {
  entryId: string;
  values: {
    name: string;
    sku: string;
    description: string | null;
    price: number | null;
    onSale: boolean | null;
  };
}

interface ProductListingInputs {
  heading: string;
  products: ResolvedContentEntryQuery<Product>;
}

export function ProductListing({
  inputs: { heading, products }
}: ComponentProps<ProductListingInputs>) {
  const { items, hasMore, loading, loadMore } = useContentEntryList(products);

  return (
    <section className="py-12 px-6">
      {heading && <h2 className="text-3xl font-bold text-center mb-8">{heading}</h2>}

      {items.length === 0 ? (
        <p className="text-center text-text-muted">No products published yet.</p>
      ) : (
        <ul className="grid gap-6 sm:grid-cols-2 lg:grid-cols-3 max-w-5xl mx-auto">
          {items.map(product => (
            <li
              key={product.entryId}
              className="border rounded-lg p-6 hover:shadow-md transition-shadow"
            >
              <h3 className="text-xl font-semibold mb-1">{product.values.name}</h3>
              <p className="text-xs text-text-muted mb-3">SKU: {product.values.sku}</p>
              {product.values.description && (
                <p className="text-sm text-text-muted mb-4 line-clamp-3">
                  {product.values.description}
                </p>
              )}
              {product.values.price != null && (
                <p className="text-lg font-bold">
                  ${product.values.price.toFixed(2)}
                  {product.values.onSale && (
                    <span className="ml-2 text-sm font-medium text-primary">On sale</span>
                  )}
                </p>
              )}
            </li>
          ))}
        </ul>
      )}

      {hasMore && (
        <div className="mt-8 text-center">
          <button
            onClick={loadMore}
            disabled={loading}
            className="px-6 py-2 rounded-md bg-primary text-white font-medium hover:bg-primary/80 disabled:opacity-50 transition-colors"
          >
            {loading ? "Loading..." : "Load more"}
          </button>
        </div>
      )}
    </section>
  );
}
```

A few things to notice:

- The component is a plain, synchronous React component. It doesn't import an SDK client or make a request on first render.
- `products` is typed as `ResolvedContentEntryQuery<Product>`. In query mode the input value has the shape `{ items, pageInfo, query }`. `items` holds the entries for the first page, `pageInfo` has `cursor`, `hasMore` and `totalCount`, and `query` holds the parameters needed to fetch the next page.
- Each item is a CMS entry. Your model's fields are under `values`, so the product name is `product.values.name`. The field names match the field IDs of the Product model.
- `useContentEntryList()` starts from the server-resolved first page and returns `items`, `hasMore`, `loading` and `loadMore`. Calling `loadMore()` fetches the next page in the browser and appends it to `items`. The **Load more** button only appears when there are more products than the limit.

<Callout type="hint">
  In query mode, reference fields come back as `{ id, modelId }` and are not expanded. That's why
  this component doesn't show the product's category name. If you need data from a referenced
  entry, use manual mode, or fetch the referenced entry separately.
</Callout>

## Step 3: Register the component

Open `editorComponents/index.tsx`. The starter kit already imports `createContentEntryInput` there for the `ContentEntryDemo` registration. Import your new component next to the other component imports:

```tsx title="editorComponents/index.tsx"
import { ProductListing } from "./ProductListing";
```

Then add this registration as the last item in the `editorComponents` array, after the `ContentEntryDemo` registration:

```tsx title="editorComponents/index.tsx"
  createWbComponent(ProductListing, {
    name: "Custom/ProductListing",
    label: "Product Listing",
    aiContext: "Lists products from the Headless CMS in a grid.",
    inputs: [
      createTextInput({
        name: "heading",
        label: "Section Heading",
        description: "The heading displayed above the product list.",
        defaultValue: "Our Products"
      }),
      createContentEntryInput({
        name: "products",
        label: "Products",
        description: "Which products to show, in what order, and how many.",
        models: ["product"],
        mode: "query",
        query: {
          sort: {
            fields: [
              { field: "values_name", label: "Name" },
              { field: "values_price", label: "Price" },
              { field: "createdOn", label: "Created On" }
            ]
          },
          limit: { default: 6, max: 24 },
          pagination: true
        },
        defaultValue: {
          modelId: "product",
          sort: { field: "values_name", order: "asc" },
          limit: 6
        }
      })
    ]
  })
```

Here's what the `createContentEntryInput` options do:

- `models` is the list of content model IDs the input works with. Query mode uses the first one, so the editor can only query products.
- `mode: "query"` makes the sidebar show query controls instead of an entry picker.
- `query.sort.fields` lists the fields the editor can sort by. Use the read API sort keys: model fields as `values_<fieldId>` (for example `values_price`), and meta fields such as `createdOn` as they are.
- `query.limit` sets the number shown in the sidebar's limit field (`default`) and the highest number the editor can enter (`max`).
- `query.pagination: true` enables "Load more" in the rendered component.
- `defaultValue` is the query stored on the page when an editor drops the component onto the canvas.

<Callout type="warning">
  Keep the `defaultValue` with a `limit`. The sidebar's limit field displays `query.limit.default`,
  but that number is only saved to the page when the editor types into the field. The SDK uses the
  saved query when it fetches entries, so without a saved limit the page would show a different
  number of products than the sidebar suggests. `defaultValue` saves `limit: 6` and a sort order as
  soon as the component is added, so the published page matches what the editor sees.
</Callout>

## Step 4: Use it in the editor

1. Restart your dev server to pick up the new component.
2. In the Admin sidebar, go to **Website Builder → Pages** and open or create a page.
3. Find **Product Listing** in the **Custom** group of the component palette.
4. Drag it onto the canvas. The preview shows your published products.
5. Click the component and use the sidebar inputs to set the heading, the sort field and order, and the number of products.
6. **Publish** the page.

## How the data flow works

```
Webiny Admin Editor
  └── Editor saves the page document to the Webiny API
         (document contains "Custom/ProductListing" with inputs:
          heading: "Our Products"
          products: { modelId: "product", sort: {...}, limit: 6 })

Next.js request / build (server)
  └── sdk.wb.getPage("/your-page-slug")
         loads the page document
         finds the "products" content entry input
         lists published entries of the "product" model with that sort and limit
         attaches the results to the document

Rendering (server, then hydrated in the browser)
  └── DocumentRenderer encounters "Custom/ProductListing"
         passes inputs.products = { items, pageInfo, query } to ProductListing
  └── ProductListing renders the cards
         useContentEntryList().loadMore() fetches the next page in the browser
```

The page stores only the query. Each time the page is rendered, the products come from the Headless CMS, so a newly published product shows up without editing the page.

## Troubleshooting

### No products showing

- Check that you published the products in Webiny Admin, not just saved them.
- Check that the content model ID in `models` matches your model. The Headless CMS chapter uses `product`.
- Check the page has a saved query. Select the component, type a number into the limit field, and publish again.

### "Custom/ProductListing" doesn't appear in the editor

- Restart the dev server. New component registrations require a restart.
- Make sure the `ProductListing` registration is inside the `editorComponents` array.

### Fewer or more products than expected

- The page uses the limit saved on the page, not the one in your code. Changing `defaultValue` or `query.limit.default` only affects components added after the change. Update existing instances in the sidebar.

### Sorting by a field fails

- Sort keys for model fields need the `values_` prefix, for example `values_name` rather than `name`.

### TypeScript error on `product.values.name`

- Check that the `Product` interface field names match the field IDs in your Webiny content model (e.g. `name` not `productName`).

## Summary

In this lesson you built a component that connects the Website Builder and the Headless CMS:

- Used `createContentEntryInput` in query mode so editors configure which products to show from the sidebar.
- Received the resolved products as an input value, fetched on the server by `sdk.wb.getPage()`.
- Added "Load more" pagination with `useContentEntryList`.
- Saved a default query with `defaultValue`, so the published page uses the limit the editor sees.

The same input covers hand-picked content too. Switch to `mode: "manual"` (with `list: true` for several entries) when editors should choose specific entries instead of a query.
